## 2. 运行前准备

### 2.1 当前工程目录

下面所有命令都默认在项目根目录执行：

```bash
/home/liwenshuo/my_project/WindCloud_V4
```

先进入项目根目录：

```bash
cd /home/liwenshuo/my_project/WindCloud_V4
```

### 2.2 必要依赖

当前工程编译时会链接这几个库：

```makefile
-lpthread -lcrypto -lmysqlclient
```

这里需要特别说明一件事：

1. 当前实际代码里的 JWT 实现文件是 [src/server/jwt.c](/home/liwenshuo/my_project/WindCloud_V4/src/server/jwt.c:1)
2. 它使用的是 `OpenSSL` 提供的 `HMAC(EVP_sha256)`、`EVP_EncodeBlock`、`EVP_DecodeBlock`
3. 当前工程的 `Makefile` 也只链接了 `-lcrypto`，并没有链接 `-ll8w8jwt`

也就是说，**当前 V4 实际实现使用的是“基于 OpenSSL 自行封装的 HS256 JWT”**，不是 `l8w8jwt`。

如果你在 [项目概述.md](/home/liwenshuo/my_project/WindCloud_V4/docs/项目概述.md:1158) 里看到 `l8w8jwt`，那一部分更接近“可选实现思路”或“方案示例”，不是当前仓库已经采用的最终代码实现。

也就是说，本地至少需要具备：

1. `gcc`
2. `make`
3. OpenSSL 开发库
4. MySQL 客户端开发库
5. 本机可访问的 MySQL 服务

### 2.3 配置文件

当前程序读取的配置文件是：

```bash
config/config.ini
```

当前默认内容如下：

```ini
ip=127.0.0.1
port=9090
db_host=localhost
db_user=root
db_pwd=123456
db_name=netdisk_db
timeout_seconds=120
log=DEBUG
server_log=../log/server.log
client_log=../log/client.log
```

如果你本机 MySQL 用户名、密码或端口不同，先改这里。

### 2.4 配置文件搜索路径说明

当前代码会按下面两个相对路径顺序寻找配置文件：

1. `../config/config.ini`
2. `./config/config.ini`

所以程序既支持：

1. 从项目根目录启动
2. 从 `bin` 目录启动

为了减少路径理解成本，建议统一从项目根目录启动。

### 2.5 日志目录和测试文件目录

当前工程里已经有：

```bash
log/
test/server_files/
test/client_files/
```

其中：

1. `log/` 用来保存服务端和客户端日志
2. `test/server_files/` 用来保存服务端真实文件内容
3. `test/client_files/` 用来保存客户端本地测试文件

`test/server_files/` 和 `test/client_files/` 在当前代码里都会按需要自动检查和创建，但本地联调时提前保留这两个目录最省事。

## 4. 启动服务端

### 4.1 推荐启动方式

在项目根目录打开一个终端，执行：

```bash
./bin/server_app
```

### 4.2 服务端启动时会做什么

按当前代码，服务端启动后会依次完成这些动作：

1. 读取 `config/config.ini`
2. 初始化日志
3. 连接 MySQL
4. 自动检查并创建数据库 `netdisk_db`
5. 自动检查并创建三张核心表：
   - `users`
   - `files`
   - `paths`
6. 初始化数据库连接池
7. 创建监听 socket，默认监听 `127.0.0.1:9090`
8. 创建线程池、时间轮和 `epoll` 主循环

### 4.3 服务端成功启动后你应该看到什么

控制台或日志中通常会出现这类信息：

```text
服务端配置加载完成
数据库 [netdisk_db] 及数据表初始化校验完成
服务端开始监听
```

如果能看到“开始监听”这一类信息，就说明服务端已经进入可连接状态。

## 6. 一轮最基础的本地测试怎么做

下面这组命令适合第一次联调时直接照着输入。

### 6.1 注册并登录

在客户端中依次输入：

```text
register user1/123456
login user1/123456
```

正常情况下，你会看到：

```text
注册成功
登录成功
```

### 6.2 先验证短命令

登录后，建议先跑这一组短命令：

```text
pwd
ls
mkdir dir1
cd dir1
pwd
touch a.txt
ls
cd ..
ls
```

这组命令主要验证：

1. 主连接是否正常
2. 目录状态是否正确同步
3. `ClientAppContext.current_path` 和服务端目录状态是否一致

### 6.3 再验证上传

先在客户端本地测试目录准备一个本地测试文件，例如：

```bash
echo "hello windcloud v4" > test/client_files/demo_upload.txt
```

然后回到客户端输入：

```text
puts demo_upload.txt
```

正常情况下，客户端会先提示：

```text
已启动上传任务: demo_upload.txt
正在计算文件哈希值...
```

随后应该看到上传完成或秒传成功之类的提示。

这一步主要验证：

1. 长短命令分离是否生效
2. 客户端是否创建了独立传输线程
3. 服务端是否通过 JWT 校验了独立传输连接
4. 线程池是否成功处理了这次上传任务
5. 服务端真实文件是否已经写入 `test/server_files/`

### 6.4 再验证下载

先把客户端本地测试目录里的同名文件删掉，避免“本地已完整，无需下载”的分支干扰：

```bash
rm -f test/client_files/demo_upload.txt
```

然后在客户端输入：

```text
gets demo_upload.txt
```

正常情况下，应看到：

```text
已启动下载任务: demo_upload.txt
下载成功: demo_upload.txt (...)
```

下载完成后，本地文件应该出现在：

```bash
test/client_files/demo_upload.txt
```

### 6.5 再验证删除

客户端可以继续输入：

```text
rm demo_upload.txt
cd dir1
rm a.txt
cd ..
rmdir dir1
ls
```

这一步主要用来确认：

1. 普通文件删除
2. 目录删除
3. 数据库逻辑路径是否正确更新

## 8. 测试过程中要注意什么

### 8.1 `puts` 和 `gets` 是异步启动的

当前客户端在执行 `puts/gets` 时会创建独立线程，因此你输入命令后，经常会先看到：

```text
已启动上传任务: ...
已启动下载任务: ...
```

然后稍后才看到真正的传输结果。

所以测试长命令时，不要刚输入完 `puts/gets` 就马上退出客户端。

### 8.2 主连接和独立传输连接不是同一条连接

这意味着：

1. `pwd`、`ls`、`mkdir`、`cd` 这些命令走主连接
2. `puts`、`gets` 会新建独立传输连接

所以如果你看到：

1. 短命令正常
2. 但上传下载失败

那么优先检查：

1. 是否已经成功登录
2. 客户端是否已经收到 token
3. 服务端日志里是否有 JWT 校验失败信息

### 8.3 空闲超时是当前设计的一部分

当前服务端主连接默认超时时间配置项是：

```ini
timeout_seconds=120
```

也就是说，如果客户端长时间不输入命令，主连接可能会被服务端关闭。  
这不是异常，而是当前第四期功能的一部分。

如果你看到客户端提示：

```text
主连接已失效，请重新登录。
```

按提示重新登录即可。

如果你想自己验证这一点，可以这样做：

1. 客户端登录成功后先不要输入新命令
2. 等待超过 `120` 秒
3. 再输入 `ls` 或 `pwd`
4. 正常情况下会先看到 `主连接已失效，请重新登录。`
5. 然后客户端重新进入登录菜单

## 10. 常见问题

### 10.1 服务端启动时提示 MySQL 连接失败

优先检查：

1. MySQL 服务是否已经启动
2. `config/config.ini` 中的 `db_host`、`db_user`、`db_pwd`、`db_name` 是否正确
3. 当前 MySQL 用户是否有创建数据库和建表权限

### 10.2 客户端一启动就提示连接失败

优先检查：

1. 服务端是否已经启动
2. `config/config.ini` 中的 `ip` 和 `port` 是否和服务端一致
3. 本机 `9090` 端口是否已被其它程序占用

如果你看到服务端启动日志里有：

```text
绑定监听地址失败，错误码=98
```

就说明当前 `9090` 端口已经被其它进程占用了。  
这时应先停掉旧的服务端实例，再启动当前版本。

### 10.3 登录成功后，`puts/gets` 仍然失败

优先检查：

1. 客户端是否真的收到了 `token_packet_t`
2. 当前主连接是否已经超时
3. 服务端日志中是否出现 JWT 校验失败
4. 当前目录路径是否已经异常

### 10.4 从项目根目录启动和从 `bin` 目录启动有什么区别

当前代码两种都兼容，但建议统一从项目根目录启动。  
这样：

1. 配置文件路径更直观
2. 日志路径更直观
3. 本地测试文件也更容易管理
