## 4.4 第五期恢复逻辑测试

### 测试目的

验证第五期本地任务记录恢复能力，也就是：

1. 客户端本地存在 `.multipart`
2. 已经有部分分片文件和 `meta.ini`
3. 再次执行 `gets` 时，能够继续完成下载

### 说明

本来计划通过“下载中途强行中断客户端或服务端”制造真实半截文件。  
但当前本地环境存在两个限制：

1. 回环环境传输速度很快，`160MB` 文件很难稳定停在中间状态
2. 当前运行环境下，难以精确直接终止服务端子进程，只能优雅退出；优雅退出时，正在进行的下载线程通常已经把当前传输完成

因此本次恢复测试采用“手工构造恢复现场”的方式验证恢复代码路径。

### 手工构造的恢复现场

针对 `z52801.bin`：

1. 本地保留原文件副本 `z52801.bin.src`
2. 删除正式下载结果 `z52801.bin`
3. 手工创建：

```text
test/client_files/.multipart/33fb789de43da3aba9e552cebf539db0ccf0d79d060eb08e1e5bfb66f8f69c5c/
```

4. 在其中放入：
   - `part_0`，大小 `64MB`
   - `meta.ini`

其中 `meta.ini` 内容为：

```ini
file_name=z52801.bin
file_hash=33fb789de43da3aba9e552cebf539db0ccf0d79d060eb08e1e5bfb66f8f69c5c
file_size=536870912
part_count=1
part_0_start=0
part_0_end=536870911
part_0_finished=67108864
part_0_ip=127.0.0.1
part_0_port=9090
```

### 测试步骤

客户端执行：

```text
gets z52801.bin
```

### 客户端实际结果

客户端输出：

```text
多点下载方案申请成功
多点下载任务已启动。
多点下载完成: z52801.bin
```

### 文件校验结果

执行：

```bash
sha256sum test/client_files/z52801.bin test/client_files/z52801.bin.src
```

结果：

```text
33fb789de43da3aba9e552cebf539db0ccf0d79d060eb08e1e5bfb66f8f69c5c  test/client_files/z52801.bin
33fb789de43da3aba9e552cebf539db0ccf0d79d060eb08e1e5bfb66f8f69c5c  test/client_files/z52801.bin.src
```

### `.multipart` 清理结果

恢复完成后再次检查：

```text

```

说明：

- 任务子目录和分片临时文件已经被清理
- 恢复完成后，最终文件已经成功合并

### 结论

- 通过
- 该测试验证了“本地已有分片文件和元数据时，`gets` 仍能完成恢复”的第五期核心逻辑

## 4.5 双数据源本地联调尝试

### 测试目的

验证第五期真正的“多数据源服务器”场景。

### 实际尝试

本次尝试额外启动第二个服务端实例，计划监听 `127.0.0.1:9091`，并让其与主服务端共享同一个测试文件目录。

### 实际结果

第二个服务端实例在数据库初始化阶段失败，日志出现：

```text
MySQL 连接失败: Can't create TCP/IP socket (1)
```

以及：

```text
Can't connect to local MySQL server through socket '/var/run/mysqld/mysqld.sock' (1)
```

### 判断

这更像是当前本地运行环境限制，而不是第五期业务逻辑本身失败，原因是：

1. 主服务端同样配置下可以正常连接数据库
2. 当前项目的单实例数据库初始化、上传、下载都能正常跑通
3. 第二实例失败点集中在“再起一个额外服务端进程时的数据库连接建立”

### 结论

- 本次未能在当前环境完成真正的“双服务端多源并行下载”联调
- 这一项仍需要在更宽松的本地环境或真实双实例环境下补测
