## 4. JWT 模块改动记录

## 4.1 改动目的

第四期中，传输连接不再依赖控制连接原有的会话状态。

客户端每次新建传输连接时，需要给服务端一个可靠的身份凭证，用来证明：

- 当前这条传输连接属于哪个用户

因此新增了 JWT 工具模块。

## 4.2 改动内容

新增了 JWT 工具头文件和实现文件，封装了两个接口：

1. `jwt_create_for_user()`
2. `jwt_verify_and_get_user()`

当前实现中：

1. 使用 `HS256`
2. 使用固定密钥
3. JWT 中包含 `uid`
4. 同时校验 `iss`
5. 同时校验 `aud`
6. 同时校验过期时间

## 4.3 编译配置改动

为了让工程可以链接 `l8w8jwt`，修改了编译选项，加入：

- `-ll8w8jwt`

## 5. 登录流程改动记录

## 5.1 改动目的

原来的登录流程只会给客户端返回一条普通文本消息。

第四期中，登录成功后客户端必须拿到：

1. `user_id`
2. `token`

因此登录响应不能再只使用普通文本包。

## 5.2 改动内容

服务端登录成功后：

1. 先根据 `user_id` 生成 JWT
2. 再把 `success/user_id/message/token` 打包到 `auth_reply_packet_t`
3. 发送给客户端

登录失败时：

1. 返回失败标记
2. 返回失败提示信息
3. 不返回 token

## 6. 客户端状态管理改动记录

## 6.1 改动目的

第四期的客户端不再只维护一个简单的 `sock_fd`。

客户端主线程和传输线程都需要共享以下信息：

1. 控制连接 fd
2. 当前登录状态
3. 当前用户 id
4. 当前 JWT
5. 当前远端虚拟路径
6. 服务端 IP 和端口

因此需要增加统一状态结构体。

## 6.2 改动内容

新增 `ClientState` 结构体，用于统一管理客户端状态。

结构体中保存：

1. `ctrl_fd`
2. `logged_in`
3. `user_id`
4. `token`
5. `current_path`
6. `server_ip`
7. `server_port`
8. `lock`

客户端主流程改成：

1. 启动时初始化 `ClientState`
2. 建立控制连接
3. 控制连接建立后先发送 `conn_init_packet_t`
4. 登录成功后把 `user_id/token/current_path` 写入 `ClientState`

## 11. 服务端连接模型改动记录

## 11.1 改动目的

原来的服务端主线程只负责 `accept`，所有连接都直接丢给线程池。

第四期要求：

1. 控制连接由主线程直接管理
2. 传输连接才交给线程池

因此服务端主流程需要重构。

## 11.2 改动内容

服务端主程序完成了以下改造：

1. 新增 `create_timer_fd()`
2. 新增 `close_control_connection()`
3. 新增 `handle_control_timeout()`
4. 新增 `handle_timer_event()`
5. 新增 `register_control_connection()`
6. 新增 `handle_accept_event()`
7. 新增 `handle_control_event()`

当前主线程逻辑变为：

1. `accept` 新连接
2. 先接收 `conn_init_packet_t`
3. 如果是控制连接：
   - 建立 `ControlConn`
   - 加入 `epoll`
   - 加入时间轮
4. 如果是传输连接：
   - 放入线程池队列

## 13. 服务端时间轮改动记录

## 13.1 改动目的

第四期要求对控制连接做空闲超时踢出。

为了避免每秒扫描全部连接，本次新增时间轮模块。

## 13.2 改动内容

新增时间轮结构和节点结构：

1. `TimeWheel`
2. `TimeWheelNode`

新增接口：

1. `time_wheel_init()`
2. `time_wheel_add()`
3. `time_wheel_refresh()`
4. `time_wheel_remove()`
5. `time_wheel_tick()`

当前时间轮工作方式为：

1. `timerfd` 每秒触发一次
2. 主线程推进时间轮一格
3. 当前槽位中的连接如果超过超时时刻，就关闭
4. 控制连接每处理一次命令后刷新超时位置

## 16. 当前限制与说明

虽然第二阶段核心代码已经完成，但当前仍需注意以下几点：

1. 本次已完成编译验证，但还没有在完整数据库和真实交互场景下做系统联调记录。
